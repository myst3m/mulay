# 115: Clay の循環の警告 (0.111.1 から): mulay の 12 件はすべて clay の誤検知で、clay が直した

日付: 2026-11-02。状態: 採用。

## 背景

clay 0.111.1 は、Atom・Chan への書き込みで、書く値の型から同じ型の入れ物に届くとき「循環になりうる」と警告する
(clay の docs/development/experiments/243-cycle-warn)。型だけで判定し、黙らせる書き方は無い。
消すには、入れ物を大域 (def) にするか、型を変える。

mulay の本体では 12 件出た。

- 10 件は clay.core の delay が原因だった。delay が thunk の `Fn(Int)` を Dyn にしていたので、型が `Fn(Int)` の closure がすべて
  Dyn から届く扱いになっていた。mulay は DW の評価の Ctx を Dyn で持つので、DB のプール、VM のキュー、Anypoint MQ、
  エンジン、タイムゾーンの表に警告が出た。
  clay に最小の再現を送り、clay が直した (d1c14944)。
- 残る 2 件は dw/eval.clay の parts-reader にあった (下)。

## parts-reader の 2 件 (clay が直した)

`{(a), b: 1, (seq)}` のような、部分を広げるオブジェクトのフィールドを読む関数である。
開いた列の反復子を `Atom(Vec(Fn(Int Values(Val ..))))` に持つ。型の上では反復子が読み手を捕まえうるので、警告になっていた。
実際には、反復子は `(:open q)` が作り、q は読み手より前にできる。open には Int しか渡らないので、輪にはならない。

人が警告ごとに「輪にならない」と調べるのは続けられない (ユーザー、2026-11-02)。そこで clay と相談し、clay が検査を細かくした (40fcb99b)。
新しい規則は次のとおり。

- 書き込む値は、置き場より後に作られる。
- だから、値の材料のどの型からも同じ型の置き場に届かなければ、輪は閉じない。材料とは、局所変数・読むだけの置き場の中身・大域の値である。

mulay の形は変えていない。直った clay で組むと、mulay の警告は 0 になる。

## 方針

- 循環の警告は mulay 側で黙らせない。誤検知なら clay に最小の再現を送って、検査を直してもらう。本当の輪なら mulay を直す。
- 0.111.1 では 12 件出た。両方の修正が入った clay 0.111.2 で組むと 0 件になる (2026-11-02 に確かめた)。
